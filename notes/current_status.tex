\section{Naming and Scope}
The project name used in report-facing text should be \textbf{PURE}: \emph{Predicate-aware Uncropped Relation Embedding}. The companion diagnostic dataset and benchmark should be \textbf{CORE}: \emph{Compositional Relation Evaluation}. Avoid the older labels \texttt{PURE-v3}, \texttt{PURE-SPOA}, and \texttt{COMPREL-OV} in final report sections unless they are explicitly described as historical draft names.

\section{Maintained Architecture}
PURE is a compact one-stage relation model for VG150-style scene graph prediction. It keeps dense CLIP ViT-L/336 vision tokens active, grounds object nodes with box-conditioned deformable routing, and builds ordered subject--object relation embeddings through Fourier geometry and vector-gated semantic--geometric fusion. Predicate scoring is reported through classifier, CLIP-text, ensemble, and calibrated variants rather than being collapsed into a single opaque score.

The current code also includes an experimental \textbf{adaptive calibration} path. When enabled, the predicate classifier logits are augmented by a learnable sample-level bias residual and an adaptive prior gate. This turns the earlier fixed frequency-prior trick into a trainable calibration mechanism, while remaining optional so that older checkpoints and no-prior baselines remain comparable.

\section{Training Objective}
Report the objective as three main pillars rather than a long list of independent losses:
\begin{enumerate}[leftmargin=1.5em]
  \item \textbf{PredCE-LA}: predicate cross-entropy with optional logit adjustment for long-tail predicates;
  \item \textbf{Counterfactual-SPOA}: queue-based text alignment with role/predicate counterfactual regularization inside the SPOA alignment term;
  \item \textbf{Dense Grounding}: query-to-pair grounding that keeps visual evidence tied to the dense image field.
\end{enumerate}
The adaptive calibration extension adds a small regularized calibration term only when the adaptive calibration flag is enabled. Visual hard negatives, bilinear mixing, object-language anchors, and relation-context scaling are not maintained defaults. Recent ablations showed that these branches reduce mean recall under the calibrated L3 protocol, so they should be presented only as negative ablation evidence if mentioned.

\section{Curriculum}
The maintained code path is intentionally narrow:
\begin{itemize}[leftmargin=1.5em]
  \item \texttt{core}: freeze CLIP, disable object language anchors, disable relation context, disable bilinear mixing, and disable frequency calibration during training. This phase forces deformable routing and the relation decoder to learn visual evidence.
  \item \texttt{adaptive calibration}: optionally train a bias-aware calibration head on top of the predicate classifier using an adaptive prior gate and a bounded residual logit correction.
  \item \texttt{eval}: keep the core architecture and sweep classifier, text, ensemble, and frequency/adaptive calibration variants for transparent reporting.
\end{itemize}
This curriculum is the report-friendly alternative to the older branch-ramp and scaling-branch debugging workflows.

\section{Branch-Ramp Interpretation}
Branch-ramp runs are diagnostic engineering experiments used to identify which modules help or hurt. They are not the final methodological story. If mentioned in the report, they should appear only as an implementation note or ablation rationale: visual-hard negatives, bilinear mixing, object-language anchors, and relation-context scaling were tested, found unstable for mean recall, and moved out of the maintained path.

\section{CORE Status}
CORE is a real generated diagnostic dataset with several thousand images organized into six relation groups through the pipeline described in the report draft. It has not yet been used as the primary training or evaluation source for PURE. The final report should state this clearly and frame CORE as a future evaluation/training resource once its scale, audits, and protocol are sufficiently stable.

\section{Immediate Reporting Guidance}
\begin{itemize}[leftmargin=1.5em]
  \item Use \textbf{PURE} and \textbf{CORE} consistently, with full English names at first mention.
  \item Do not claim SOTA unless the exact protocol, split, graph constraint, object-label source, and calibration setting match the compared methods.
  \item Separate no-prior model metrics from eval-time Bayesian/frequency calibration metrics and from trainable adaptive calibration metrics.
  \item Report SGCls only with predicted object labels, e.g., CLIP object classification; GT object labels are PredCls-only.
  \item Move CORE training/evaluation claims to future work unless new completed runs are available.
\end{itemize}
